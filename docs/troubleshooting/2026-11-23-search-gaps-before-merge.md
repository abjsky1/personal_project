## 남긴 것 (고치지 않음)

- `q`를 두 번 보내면(`?q=a&q=b`) 쉼표로 이어 "a,b"로 찾는다. 화면이 만드는 주소에는 없고, 해가 없다
- 입력칸의 `maxlength`는 글자를 UTF-16 칸으로 세서 이모지는 15개까지 들어간다 (서버는 30자). 음식 이름에 이모지를 쓸 일이 드물다
- 100단보다 깊게 겹친 JSON은 `JSON_VALID` 자체가 오류를 내서 모든 검색이 500이 된다. 앱은 평평한 배열만 쓰므로 DB를 손으로 고칠 때만 생긴다 (코드 주석에 적음)
- 검색에는 횟수 제한이 없다. 지금 규모에서는 한 번에 몇 ms라 두지 않았다 ([prevent-server-resources](prevent-server-resources.md) 14번)

## 재발 방지

- 검토에서 찾은 것을 한 번에 재현하는 스크립트를 기록 저장소에 남겼다. 고치기 전과 뒤를 같은 스크립트로 돌린다
- 띄어쓰기, 빈칸 글자, 30자 자르기는 `PostSearchTest`에 넣었다
- 미리 막은 것은 [prevent-server-resources](prevent-server-resources.md) 14번, [prevent-security-privacy](prevent-security-privacy.md) 12번

## 배운 것

- 공통 스크립트를 고칠 때 "값이 없을 때"를 먼저 시험한다. ④를 고치며 눌러 본 길은 모두 값이 있는 길이라 ⑤를 놓쳤다
- 공통 CSS 규칙(`form button`)은 새 form에 그대로 걸린다. 새 form을 더하면 휴대폰과 PC를 처음부터 찍어 본다
- 한국어 검색은 띄어쓰기가 사람마다, AI마다 다르다. 글자 그대로 찾기로 시작하더라도 띄어쓰기는 처음부터 빼고 견준다
