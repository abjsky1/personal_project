# 배포 직후 화면마다 첫 요청이 2~3초 걸린다 (JSP 첫 컴파일)

- **종류**: 찾은 문제 (측정)
- **발견**: 2026-11-18, JM-91 기준선. 밖에서 잴 때 공지 목록 10번 중 첫 번째만 2,347 ms가 나와 nginx 기록으로 따라갔다
- **상태**: 할 일 (개선 후보. 일감은 시작할 때 만든다)
- **영향**: 배포 뒤 각 화면을 처음 연 사람이 2 ~ 3초, 길면 6초 넘게 기다린다. 하룻밤에 여러 번 머지하는 날은 그때마다 겪는다

## 현상

nginx 기록 14일치(11-04 ~ 11-18)에서 배포 18번 각각의 뒤에 화면마다 처음 온 요청을 나머지와 비교했다 (bot 포함).

| 화면 | 배포 뒤 첫 요청 가운데 (최대) | 1초 넘은 첫 요청 | 나머지 요청 가운데 |
|---|---|---|---|
| 피드 | 2,906 ms (6,502 ms) | 18번 중 14번 | 27 ms |
| 글 상세 | 2,790 ms (4,273 ms) | 18번 중 17번 | 37 ms |
| 글쓰기 화면 | 2,378 ms (3,519 ms) | 15번 중 10번 | 3 ms |
| 공지 | 2,673 ms (6,730 ms) | 13번 중 8번 | 19 ms |
| 피드백 | 2,363 ms (6,346 ms) | 17번 중 12번 | 15 ms |

- 2026-11-19 10:06 PR #49 배포 직후에도 첫 화면 요청이 5.9초 걸렸다 (bot User-Agent로 확인)
- CloudWatch 앱 기록(11-04 ~ 11-19)에서 덜 열리는 화면의 p95가 높은 것도 같은 까닭이다: 글쓰기 p50 2 ms인데 p95 2,411 ms, 공지 목록 p50 17 ms인데 p95 884 ms

## 원인

JSP는 처음 요청이 올 때 자바 코드로 바뀌고 컴파일된다. 배포로 app 컨테이너가 새로 뜨면 모든 JSP를 처음부터 다시 컴파일하고, JVM도 아직 데워지지 않아(JIT) 첫 요청이 오래 걸린다. 운영 설정은 JSP 개발 모드를 껐지만(`server.servlet.jsp.init-parameters.development=false`, 파일이 바뀌었는지 매번 보지 않음), 미리 컴파일하지는 않는다.

## 앞으로 해결해 나갈 것

1. 가장 작은 방법: `deploy/deploy.sh`가 healthy를 확인한 뒤 주요 화면(첫 화면, 글 상세 하나, 글쓰기, 공지, 피드백)을 bot User-Agent로 한 번씩 불러 둔다. 몇 줄이고, 배포 스크립트라 운영자가 직접 쓴다
2. 더 근본적인 방법: 빌드할 때 JSP를 미리 컴파일한다 (Jasper의 JspC). 빌드 시간과 설정이 늘어나는 것과 견준다
3. 무중단 배포(JM-62)를 하면 새 app을 데운 뒤에 넘길 수 있어 함께 정리된다 ([2026-11-10-deploy-502](2026-11-10-deploy-502.md))
4. 목표: 배포 뒤 첫 요청 가운데 2.4 ~ 2.9초 → **0.1초 미만**

## 재는 법
