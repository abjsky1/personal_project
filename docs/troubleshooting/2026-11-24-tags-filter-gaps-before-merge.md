- **종류**: 찾은 문제 (DB, AI 비용, 화면). JM-83 음식 태그와 필터를 만드는 동안 테스트, 화면 찍기, PR 전 검토로 찾았다. 모두 운영에 나가기 전에 고쳤다
- **발견**: 2026-11-24
  - ①②: 실제 DB로 도는 테스트와 표 모양 확인
  - ③: draft1 화면을 찍을 때
  - ④~⑪: PR 전 검토, 에이전트 둘이 따로 봤다 (데이터와 AI 비용, 화면과 보안)
    - 데이터 쪽: 운영과 같은 옛 표에 칸을 더하는 것, 옛 버전 앱이 함께 저장하는 것, 동시에 바꿔 쓰는 것을 따로 만든 DB에서 실제로 돌렸다
    - 화면 쪽: 헤드리스 Chrome으로 뒤로 가기, 끌기, 너비별 모양을 돌렸다
    - 반박 확인은 에이전트를 더 띄우지 않고, 고치기 전후를 같은 스크립트와 테스트로 직접 재현해서 했다

- **영향**: 그대로 나갔다면 다음 일이 있었다
  - 태그가 하나도 저장되지 않았다(①)
  - 나중에 태그 값을 더할 때 저장이 실패했다(②)
  - AI가 잠깐 장애일 때 지난 글들이 태그를 영영 못 받았다(⑤)
  - 필터를 쓰고 뒤로 가면 칼로리 칸이 잠긴 채 남았다(⑨)

## 현상과 원인과 해결

| | 찾은 방법 | 현상 (고치기 전) | 원인 | 해결 | 확인 (고친 뒤) |
|---|---|---|---|---|---|
| ① | 테스트 (`PostTagFillerTest`) | 태그를 바꿔 쓰면 태그가 하나도 남지 않았다 | 태그를 넣고(아직 DB로 보내지 않은 INSERT) "채웠음"을 적는 UPDATE의 `clearAutomatically`가 JPA의 기억을 비우면서 INSERT를 버렸다 | UPDATE 전에 먼저 보낸다 (`flushAutomatically`) | 테스트 통과, 로컬 글 27개에 태그가 저장됨 |
| ② | 표 모양 확인 (`SHOW CREATE TABLE`) | `post_tags.tag`가 MySQL `ENUM` 칸으로 만들어졌다 | `@Enumerated(STRING)`만 두면 Hibernate가 MySQL에서 ENUM을 만든다. ENUM 칸은 값을 더할 때 ddl-auto가 고치지 못한다 (S1과 2026-11-02 기록에서 겪은 것) | `@JdbcTypeCode(VARCHAR)` (다른 enum 칸과 같은 규칙), 로컬 표는 지우고 다시 만듦 | `varchar(20)` |
| ③ | draft1 화면 찍기 | 휴대폰에서 펼친 칸의 칼로리 칩 16개가 화면을 차지해 사진이 한참 아래로 밀렸다 | 피드 위에 늘 보이는 칸을 두었다 | 운영자 검토로 찾기 옆 [필터] 단추와 겹쳐 뜨는 창, 칼로리는 최소와 최대 두 칸 (draft2, draft3) | 피드 모양은 그대로, 버튼 하나만 더해짐 |
| ④ | 검토, 코드 | 사진 저장소(S3) 오류가 나면 태그 채우기 한 회차가 통째로 멈추고 ERROR 로그로 에러 메일이 갈 수 있었다 | 글 하나의 처리가 AI 실패(`FoodAnalysisException`)만 받았다 | 글마다 모든 오류를 받아 그 글의 실패로 남기고, 사진 저장소 오류는 "답을 받지 못함"(IMAGE_LOAD)으로 본다 | 테스트 (사진 저장소가 오류를 내면 횟수 0, AI를 부르지 않음. 예상하지 못한 오류는 실패 하나) |
| ⑤ | 검토, 코드 | Gemini가 한 시간 장애면 지난 글 80개쯤이 3번을 다 써 영영 채워지지 않았다 | 장애(429, 5xx, 연결 실패)도 맡은 횟수를 썼고, 회차는 20개를 차례로 계속 불렀다 | 답을 받지 못하면 맡은 것을 돌려주고(`releaseTagging`) 그 회차를 멈춘다 | 테스트 (503이면 한 번만 부르고 멈춤, 두 글 모두 횟수 0, 다음 회차에 다시 찾음) |
| ⑥ | 검토, 코드 | 하루 분석 횟수에 태그 호출을 글 수로 세서, 한 글을 세 번 부르면 한 번으로 셌다 | 맡을 때마다 `tag_called_at`을 덮어써서 글 하나에 한 줄 | 오늘 부른 글의 맡은 횟수를 모두 더한다 (조금 많게 셀 수 있는 쪽) | 테스트 (두 번 맡으면 2) |
| ⑦ | 검토, 코드 | AI가 응답하지 않으면 태그 채우기 한 회차가 12분까지 걸리고, 그동안 분석 다시 넣기가 기다렸다 | 일정 스레드가 하나 (Spring 기본값) | 일정 스레드 둘 (`spring.task.scheduling.pool.size=2`), ⑤로 장애 때는 한 번만 부르고 멈춤 | 설정 |
| ⑧ | 검토, 코드 | 카드에 800 kcal로 보이는 글(799.6)이 "800 이상" 필터에 나오지 않았다 | 카드는 반올림한 숫자, 필터는 소수 그대로 견줬다 | 필터도 반올림한 값으로 견준다 | 테스트 (799.4는 800 미만, 799.6은 800 이상) |
| ⑨ | 검토, 재현 | [적용] 뒤 뒤로 가기를 하면 필터 창이 열린 채 돌아오고 칼로리 칸 두 개가 잠겨 있었다 | 비어 있는 칼로리 칸을 보내지 않으려고 칸을 잠갔는데(disabled), 브라우저가 저장해 둔 화면에 잠긴 채 남았다 | 칸을 잠그지 않고 보낼 값에서 뺀다(`formdata`). 저장해 둔 화면으로 돌아오면 창을 닫고 지금 필터로 되돌린다 | 같은 스크립트: 창 닫힘, 칸 잠기지 않음 |
| ⑩ | 검토, 재현 | 창을 ✕로 닫았다 다시 열면 적용하지 않은 선택이 남아 있었다. 뒤로 가기로 돌아오면 적용하지 않은 한식이 체크돼 있었다 | 창의 칸 값을 지금 걸린 필터로 되돌리지 않았고, 브라우저가 칸 값을 되살렸다 | 열 때마다 `form.reset()`, `autocomplete="off"` | 같은 스크립트: 고기 체크 안 됨, 한식 체크 안 됨 |
| ⑪ | 검토, 재현 | 필터를 고른 피드에서 뒤로 가기로 빠져나온 뒤 글을 열면 "← 목록"이 그 필터 화면으로 데려갔다 (쪽 번호는 전부터 그랬다) | "보던 목록" 스크립트가 처음 열릴 때만 돌고, 브라우저가 저장해 둔 화면으로 돌아올 때는 다시 돌지 않았다 | `pageshow`에서도 지금 주소를 다시 적는다 | `back:url:/`가 `/`, "← 목록"이 `/` |

## 함께 고친 작은 것

- 창 안에서 끌어 밖에서 놓으면 창이 닫혔다 → 누른 곳과 뗀 곳이 모두 바깥일 때만 닫는다
- 필터를 고른 피드가 검색 엔진에 올라갈 수 있었다 → 검색 결과처럼 `noindex`
- ✕ 단추가 30 x 32px → 44 x 44px
- 휴대폰에서 창이 열린 동안 뒤의 피드가 스크롤됐다 → 막는다 (PC는 스크롤 막대가 사라져 화면이 흔들려서 휴대폰만)
- dialog를 모르는 옛 브라우저(iOS 15.3 이전)에서는 창이 늘 펼쳐져 있었다 → 열기 전에는 숨기고, 단추를 누르면 화면 안에 펼친다
- 태그만 묻는 지시문의 문장이 응답 형식과 달랐다 (형식이 이겨서 해는 없었다) → 맞춤

## 배운 것

- `@Modifying(clearAutomatically)` 쿼리를 다른 저장과 한 트랜잭션에 두면, 앞에서 저장한 것이 DB로 가기 전에 지워질 수 있다. 테스트가 실제 DB로 "저장한 뒤 다시 읽기"를 했기 때문에 잡았다
- 새 표를 만들면 칸 모양(`SHOW CREATE TABLE`)을 꼭 본다. 코드만 봐서는 ENUM이 생기는 줄 모른다
- 뒤로 가기는 "브라우저가 저장해 둔 화면"과 "다시 받아 칸 값만 되살린 화면" 두 가지가 있다. 둘 다 시험한다
- 외부 API의 잠깐 장애는 "실패"가 아니라 "아직 안 함"으로 다룬다. 횟수 제한이 장애를 영구 실패로 바꾼다
