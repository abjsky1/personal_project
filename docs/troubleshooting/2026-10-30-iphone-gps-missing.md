# 2026-10-30 · 위치 제공에 동의했는데 아이폰 사진의 위치가 저장되지 않음

| 항목 | 내용 |
|---|---|
| 발견 | S1 휴대폰 실기기 테스트 (아이폰 Safari) |
| 심각도 | 낮음 — 글은 정상으로 올라가고, 위치(선택 기능)만 빠짐 |
| 상태 | 원인 확인, 코드 문제 아님 (아이폰이 사진을 넘겨주는 방식의 차이) |

## 현상
- 위치 제공에 동의하고 아이폰으로 올린 3장(28~30번) 모두 위치와 촬영 시각이 저장되지 않았다.
- 로그에는 `Location consented but no GPS in photo: postId=28`처럼 "동의했지만 사진에 GPS가 없음"만 남았다.

## 조사 과정
1. **우리가 못 읽은 것인지, 처음부터 없었던 것인지**부터 구분해야 했다.
   - 정보를 읽다가 실패하면 남도록 해 둔 `Unreadable photo metadata` 경고는 없었다 → 읽기는 성공했다.
   - 그런데 GPS뿐 아니라 **촬영 시각까지** 없었다. 아이폰이 정보를 통째로 지운 건지, 일부는 왔는데 우리가 놓친 건지는 이 로그만으로 알 수 없었다.
2. 사진에 **어떤 정보 칸이 들어 있었는지**를 남기는 로그를 추가했다. 좌표·시각 값은 남기지 않고 종류와 있음/없음만 남긴다.
   ```
   Photo metadata: directories=[...], gps=..., takenAt=...
   ```
3. 같은 아이폰으로 방법을 바꿔 가며 다시 올렸다.

| 올린 방법 | 로그 | 결과 |
|---|---|---|
| 사진 보관함에서 고르기 | `[JPEG, Exif IFD0, Exif SubIFD, Apple Makernote, Apple Run Time, GPS, Exif Thumbnail, ICC Profile, ...]` `gps=true, takenAt=true` | 위치·촬영 시각 저장됨 (40번) |
| 올리기 화면에서 바로 찍기 | `[JPEG, JFIF, Exif IFD0, Exif SubIFD, ICC Profile, Photoshop, IPTC, ...]` `gps=false, takenAt=false` | 없음 |

## 원인
- **사진 보관함에서 고른 사진**: 아이폰 카메라가 찍을 때 만든 원본 정보가 그대로 온다. `Apple Makernote`는 아이폰 카메라가 남기는 정보 칸이다.
- **브라우저에서 바로 찍은 사진**: 아이폰이 브라우저에 넘겨주려고 사진 파일을 **새로 만들면서** 위치와 촬영 시각을 넣지 않는다. 카메라 원본에는 없는 `Photoshop`, `IPTC`, `JFIF` 칸이 있는 것이 새로 만든 파일이라는 표시다.
- 우리 코드는 두 경우 모두 들어온 정보를 정확히 읽었다.

## 해결
- 코드 수정은 없다. 기획서 6.2절에 "iOS Safari 등 일부 브라우저는 업로드할 때 위치 정보를 지워서 보내기도 한다. 수집률을 지표로 측정한다"로 미리 적어 둔 경우였다.
- 조사용으로 넣은 `Photo metadata` 로그는 운영 지표로 남긴다. 배포 후에는 이 로그로 "동의한 사람 중 실제로 위치가 들어오는 비율"을 기기·방법별로 셀 수 있다.

## 후속 아이디어 (백로그)
- 글쓰기 화면 안내에 "위치를 남기려면 사진 보관함에서 골라 주세요"를 추가할지 → 실제 수집률을 보고 결정.
- 브라우저 위치 기능(올리는 순간의 현재 위치)을 쓰는 방법 → https에서만 동작하므로 S4 배포 후 검토. 사진을 찍은 곳과 올리는 곳이 다를 수 있다는 점도 고려해야 한다.

## 배운 점
- "값이 없다"는 결과만으로는 원인을 알 수 없었다. **무엇이 있었는지**를 남기는 로그 한 줄을 넣자마자 바로 구분됐다. 다만 로그에는 개인정보(좌표 값)가 아니라 종류만 남겼다.
- 테스트용 사진(코드로 만든 EXIF)으로는 실제 기기의 동작을 알 수 없다. 기기 테스트는 "올리는 방법"까지 바꿔 가며 해야 한다.
