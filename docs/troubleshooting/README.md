# 트러블슈팅 기록

> 찍먹을 만들고 운영하면서 만난 문제, 측정과 점검으로 찾은 문제, 문제가 되기 전에 미리 막은 것을 모두 남긴다.
> - 겪은 문제는 원인과 해결과 재발 방지를, 찾은 문제는 앞으로 해결해 나갈 순서와 재는 법을, 미리 막은 것은 어떻게 막았고 실제로 어떻게 확인됐는지를 적는다
> - 숫자의 원본(요청 하나하나, 스크립트)은 비공개 기록 저장소 `jjikmuk_update_picture`에, 성능 숫자의 모음은 [`performance.md`](../performance.md)에, 스프린트마다의 짧은 기록은 [`SPRINTS.md`](../SPRINTS.md)의 "만난 문제"에 있다
> - **고치기 전의 보안 약점은 여기에 쓰지 않는다.** 공개 저장소라 공격의 길잡이가 될 수 있어서, 비공개 기록 저장소의 `troubleshooting/`에 먼저 적고 고친 뒤에 전후와 함께 이 폴더로 옮긴다

## 세 가지 기록

| 종류 | 파일 이름 | 적는 것 |
|---|---|---|
| 겪은 문제 (장애, 버그) | `YYYY-MM-DD-제목.md` | 날짜, 영향 / 현상 / 원인 / 해결 / 재발 방지 / 배운 것 |
| 찾은 문제 (측정, 점검) | `YYYY-MM-DD-제목.md` | 종류, 발견, 상태, 영향 / 현상(숫자) / 원인 / 앞으로 해결해 나갈 것(순서와 목표 숫자) / 재는 법 / 기록 |
| 미리 막은 문제 (예방) | `prevent-영역.md` | 항목마다 예상한 문제 / 미리 한 것(코드와 설정) / 언제(커밋) / 확인(실제 숫자나 시험) / 남은 것 |

찾은 문제를 고치면 같은 파일의 상태를 "해결"로 바꾸고 전후 숫자를 더한다. 고친 방법이 미리 막는 장치가 되면 `prevent-` 파일에도 한 항목을 더한다.

스프린트 기록에만 있는 것 ([`SPRINTS.md`](../SPRINTS.md)의 스프린트별 "만난 문제" 표에 원인과 해결이 있다):

- **S1 게시판**: 주석 속 `\u` 때문에 컴파일 에러, `status`가 MySQL ENUM으로 생김, 삭제 실패 뒤 주소에 `;jsessionid=`가 붙음(세션 번호를 쿠키로만 주고받게 고침), 고친 `build.gradle`을 VS Code가 다시 읽지 않음, CSS를 고쳐도 화면이 그대로, 안드로이드에서 PC 주소가 안 열림(IPv6), 안드로이드 사진도 위치 없음
- **S2 AI 분석**: `carbs_g`가 아니라 `carbsg` 컬럼이 생김, 고친 CSS가 안 보임(배포 구성은 CSS 지문으로 해결)
- **S4 배포**: SSH가 서버 내부 IP로 접속해 시간 초과, 서버 명령이 내 PC에서 실행됨, RDS 백업 보관 기간이 무료 플랜 최대를 넘음, 서버에 `docker compose`가 없음, Route 53에서 도메인을 못 삼(가비아에서 구입)
- **S3 댓글, 피드백, 운영**: 따로 돌리면 통과하는 테스트가 전체에서는 실패(개발 DB에 남은 글), 어제까지 되던 SSH가 시간 초과(집 공인 IP가 바뀜)
- **S5 지인 베타**: 휴대폰 3칸 피드에서 왼쪽 칸만 넓음(사용자가 발견), 가비아의 `root.crt`를 빼고 합칠 뻔함, 가비아 신청서의 인증 방식이 "메일"로 돌아감, 좋아요 횟수 제한을 IP 기준으로 만들었다가 처리방침 때문에 바꿈
- **S6 고쳐 쓰는 AI**: 직접 적은 이름의 쉼표로 음식이 둘로 나뉠 뻔함, 덮어써진 예전 답변이 남지 않음(답변을 이어 달기로), **발표 중 같은 와이파이의 20명 가까이가 업로드에 막힘(JM-79)**, 쌓아 둔 PR의 필수 검사가 돌지 않음, Docker Desktop이 꺼져 DB 테스트가 모두 실패
