2app 서버

사진 처리

진짜 사진인지 검사하고 방향을 바로잡는다.

위치 같은 숨은 정보(EXIF)를 지운다.

긴 변 1280px로 줄이고 썸네일 600px을 만든다.

3S3, RDS

저장

사진 두 장은 S3에 넣는다.

글과 분석 대기(PENDING) 기록은 RDS에 한 번에 저장한다.

4브라우저

글 화면으로 이동

저장이 끝나면 바로 글 상세가 열린다.

결과 자리에는 "칼로리를 분석하고 있어요"가 보인다.

2뒤에서 분석한다
일꾼 2명이 차례로 처리한다 (대기 줄 50칸)
5app 서버

하루 상한 확인

오늘 AI 호출이 200번을 넘었으면 부르지 않는다.

그 글은 상한 초과로 남는다.

횟수는 DB에서 센다배포로 서버가 다시 켜져도 오늘 횟수가 0으로 돌아가지 않는다.

메모와 닉네임은 보내지 않는다.

답의 형식이 모양의 JSON으로만 답하라
7Gemini

AI가 답한다

정해진 모양의 JSON으로만 답한다.

30초 안에 답이 없으면 실패.

예시{ "isFood": true, "items": [ { "name": "김치찌개", "amountG": 350, "kcal": 280, "carbsG": 14, "proteinG": 22, "fatG": 15 } ], "confidence": "MEDIUM", "comment": "한 줄 설명" }
8RDS

검사하고 저장

음수이거나 지나치게 큰 값이면 실패로 처리한다.

결과와 함께 모델, 토큰 수, 걸린 시간을 저장한다.

상태가 DONE으로 바뀐다.

실패로 남는 경우답이 비었을 때, 시간 초과, 이상한 값, Gemini 쪽 오류

9브라우저

끝났는지 묻는다

글 화면이 2초마다 /api/posts/{번호}/analysis에 묻는다. 60초가 지나면 멈춘다.

10브라우저

결과가 보인다

끝났으면 화면을 새로 연다. AI 줄(칼로리, 탄, 단, 지)과 음식 표가 나온다.

+"내가 확정할게요"로 올린 글은 여기가 다르다
AI의 첫 답은 지우지 않고, 확정한 값을 따로 쌓는다
가Gemini

후보를 받는다

6, 7번에서 지시문이 달라진다.

음식마다 후보 3개와 100g당 영양을 받는다.

첫 후보가 AI의 첫 답으로 저장된다.

나브라우저

고르고 양을 고친다

글 화면에서 맞는 후보를 고르고 양(g)을 고친다.

사진에 없는 음식은 뺀다.

후보에 없으면 이름을 직접 적는다.

다app 서버

서버가 계산한다

고른 후보는 AI를 다시 부르지 않고 100g당 값에 양을 곱한다.

직접 적은 이름이 있을 때만 AI를 한 번 더 부른다 (답은 참, 거짓과 숫자만).

라RDS

확정은 한 번만

확정한 값을 저장하면 다시 바꿀 수 없다.

화면에는 AI 줄 아래에 REAL 줄이 함께 보인다.

글 하나에 AI 호출은 최대 두 번.
