# 스프린트 기록

> 이 프로젝트가 **실제로 어떻게 흘러갔는지** 남기는 기록이다.
> - 무엇을 만들지, 무엇을 정했는지(계획과 결정의 최신 상태) → [`PLANNING.md`](PLANNING.md)
> - 실제로 무엇을 했고, 무엇에 막혔고, 무엇을 바꿨는지(진행 기록과 회고) → **이 파일**
> - 문제 하나하나의 원인과 해결 과정 → [`troubleshooting/`](troubleshooting/)
>
> 스프린트가 끝날 때마다 아래 틀로 한 칸씩 추가한다. 회고(KPT)는 직접 고쳐 쓴다.

## 한 조각을 만드는 흐름

```
1. 정하기   PLANNING 15절의 조각 표에서 다음 조각을 고른다
2. 만들기   DB(엔티티) → 서비스 → 화면(JSP) + 테스트를 한 번에
3. 확인     테스트 통과 → 확인용 DB로 실제 실행 → (필요하면) 휴대폰으로 직접
4. 남기기   커밋(feat / fix / chore) → main에 push → CI ✅ 확인
5. 막히면   로그(traceId)로 원인 찾기 → 고치기 → troubleshooting/에 기록
6. 끝나면   이 파일에 스프린트 기록 + 회고(KPT), PLANNING의 조각 표, 결정 갱신
```

### 바뀐 결정
- 분석 결과 사용자 보정: 처음부터 제외 → 올릴 때 "내가 보고 확정"을 고른 글에 추가 (JM-74)
- 확정 횟수: 여러 번 다시 고칠 수 있음(첫 안) → 글마다 한 번 (나중에 데이터로 쓰기 쉽게)
- 확정할 때의 확인: 항상 글 비밀번호(첫 안) → 방금 올린 브라우저는 비밀번호 없이
- 확정한 뒤의 표시: 확정한 값이 AI의 답을 대체 → AI의 값과 확정한 값을 함께 (AI, REAL)
- 합계 표시: 큰 칼로리 숫자 아래에 탄수화물, 단백질, 지방 → 가로 한 줄에 칼로리, 탄, 단, 지와 꼬리표
- 삭제된 피드백: 목록에서 빠짐 → 줄을 남겨 번호와 안내 글만 보여 줌. 공지와 피드백 목록에 글 번호 (JM-76)
- 운영자 답변: 글마다 한 칸이라 다시 달면 덮어씀 → 달 때마다 한 줄씩 쌓여 순서대로 모두 보임. 예전 답변도 순서대로 되살림 (JM-77)
- 답변 글의 말투: 정해 둔 것이 없어 해요체와 합니다체가 섞임 → 문어체로 쓰고, 한 글의 첫 답변은 "피드백 감사합니다 :)"로 끝냄 (JM-77, 운영자)
- 업로드 한도: IP마다 1분 3번, 하루 30번 → 브라우저마다 1분 5번, 하루 30번 + IP 하루 200번 + 전체 하루 500개 (JM-79, 발표 중 발견)
