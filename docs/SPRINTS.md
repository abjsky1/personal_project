# 스프린트 기록

> 이 프로젝트가 **실제로 어떻게 흘러갔는지** 남기는 기록이다.
> - 무엇을 만들지, 무엇을 정했는지(계획과 결정의 최신 상태) → [`PLANNING.md`](PLANNING.md)
> - 실제로 무엇을 했고, 무엇에 막혔고, 무엇을 바꿨는지(진행 기록과 회고) → **이 파일**
> - 문제 하나하나의 원인과 해결 과정 → [`troubleshooting/`](troubleshooting/)
>
> 스프린트가 끝날 때마다 아래 틀로 한 칸씩 추가한다. 회고(KPT)는 직접 고쳐 쓴다.

## 한 조각을 만드는 흐름

```
1. 정하기   PLANNING 15절의 조각 표에서 다음 조각을 고른다
2. 만들기   DB(엔티티) → 서비스 → 화면(JSP) + 테스트를 한 번에
3. 확인     테스트 통과 → 확인용 DB로 실제 실행 → (필요하면) 휴대폰으로 직접
4. 남기기   커밋(feat / fix / chore) → main에 push → CI ✅ 확인
5. 막히면   로그(traceId)로 원인 찾기 → 고치기 → troubleshooting/에 기록
6. 끝나면   이 파일에 스프린트 기록 + 회고(KPT), PLANNING의 조각 표·결정 갱신
```

### 남은 확인 (안드로이드를 빌릴 수 있을 때)
- 카메라 앱 설정의 **"위치 태그"를 켜고** 새로 찍은 사진을 위치 동의와 함께 올린다.

| Route 53에서 도메인을 못 삼 (`AccessDeniedException`) | 무료 플랜 계정은 Route 53 도메인 등록을 지원하지 않음 → 가비아에서 구입, DNS도 가비아 A 레코드로 | PLANNING 10절 |
| **자동 배포가 AWS 권한 단계에서 실패** (`Not authorized to perform sts:AssumeRoleWithWebIdentity`) | GitHub이 보내는 증명서의 `sub`가 2026-07-15 이후 저장소부터 고유 번호가 붙은 새 형식인데, 콘솔 마법사가 만든 신뢰 정책은 옛 형식. 증명서 내용을 찍어 비교해서 발견 → 신뢰 정책에 새 형식 추가 | [기록](troubleshooting/2026-11-04-github-oidc-sub-claim.md) |

### 바뀐 결정
- 서버 OS: Ubuntu → Amazon Linux 2023
- RDS 자동 백업 보관: 7일 → 1일 (무료 플랜 제한, 유료 전환 때 7일로)
- 운영 DB: 서버 안 Docker MySQL → RDS (S4-1 뒤, 메모리 실측 결과)
- 서비스 이름·도메인: 찍먹, `jjikmuk.com`. 짧은 영어 조어는 거의 다 등록돼 있어서, 한국어 소리 법칙(2~3음절, 거센소리·된소리, "OO 해"가 되는지)으로 만든 이름 중 비어 있는 것을 골랐다
- 도메인 구입처: Route 53 → 가비아 (무료 플랜 제한. 가격은 연 2만 원대로 비슷)
- 백업 복구 연습: 하지 않음. 자동 백업과 런북(복구 절차)으로 갈음

### 회고 (KPT · 초안)
- **Keep**: 조각마다 밖에서(curl, 브라우저)와 **안에서**(컨테이너 안 설정, 서버 로그) 둘 다 확인했다. nginx 설정이 안 먹던 문제는 안을 들여다봐서 잡았다. "Not authorized" 같은 뭉뚱그린 오류는 설정을 더 보는 대신 실제 값(증명서 내용)을 찍어 비교해서 한 번에 풀었다. 문제 5건을 troubleshooting 기록으로 남겼다.
- **Problem**: "배포 성공"을 "설정 적용"으로 착각해 resolver 없이 두 번 배포했다. 재부팅·docker 명령을 서버가 아닌 내 PC 창에서 치는 실수가 있었다. GitHub API 조회 한도와 `gh` 없음 때문에 CI 결과를 지켜보는 게 끊겼고, 긴 커밋 제목이 PR 제목에서 잘렸다.
- **Try**: 설정을 바꾸는 PR은 "컨테이너 안에서 확인한 명령과 결과"를 PR 본문에 적는다. 서버 명령은 프롬프트(`[ec2-user@…]$`)를 먼저 보고 친다. `gh`를 설치해 PR·CI를 명령으로 다룬다. 커밋 제목은 50자 안쪽.
